# Итоговая оценка каждого снимка

`photo_score` — экспериментальная оценка видимого состояния **от 0 до 10, больше лучше**.
Это характеристика показанной части кадра. Параметры — исходная гипотеза, которую надо
проверить на ручной разметке. Оценка не измеряет качество всего двора/города или жителей.

Для повреждений, граффити и мусора исходный балл переводится в качество: `q = 10 − score`.
Для представленности деревьев/кустарников: `q = abundance_score`.

| Показатель | Базовый вес |
|---|---:|
| Дорога: повреждения | 14% |
| Тротуар: повреждения | 12% |
| Стена: повреждения | 12% |
| Стена: граффити | 6% |
| Газон: повреждения | 8% |
| Бордюр: повреждения | 7% |
| Деревья/кустарники: представленность | 10% |
| Деревья/кустарники: повреждения | 6% |
| Площадка: повреждения | 8% |
| Парковка: повреждения | 7% |
| Мусор | 10% |

Территория, присутствие объектов и различимость задают контекст и применимость
показателей. GPS, время и источник метаданных служат геопривязке и проверкам.
Подтверждённо отсутствующие объекты исключаются из числителя и знаменателя: отсутствие
парковки/стены/деревьев не штрафуется. Неуверенно присутствующие объекты учитываются
в объёме неизвестной информации. Null не заменяется нулём. Отсутствие litter по общей
схеме даёт null и исключает компонент; это не дополнительный бонус за доказанную чистоту.

Для различимого показателя коэффициент информации `v=1`, для частичного `v=0.5`,
для неоценимого `v=0`. Взвешенный итог:

```text
S = sum(w * v * q) / sum(w * v)
C = sum(w * v) / sum(w для всех присутствующих/неуверенных объектов)
```

`S` округляется до двух знаков. Минимум для выдачи балла — `C >= 0.6`, хотя бы две
оценки состояния и два разных объекта с такими оценками. Представленность растительности
сама по себе не заменяет оценку состояния. Если условия не соблюдены, снимок получает
`photo_score_status=insufficient_data` и пустой балл с объяснением. Так для каждого
снимка есть итоговый статус, а недостаток данных явно виден.

`photo_score_coverage` — покрытие информацией, **не вероятность правильности**.
Для неизвестной части рассчитываются две границы: если она вся в худшем и если вся
в лучшем состоянии. Это `photo_score_lower_bound` и `photo_score_upper_bound`,
они не являются статистическим доверительным интервалом или измеренной площадью.
Partial оставляет половину веса в неизвестной части и расширяет диапазон.

`photo_score_status=provisional` означает наличие флагов проверки. `available` означает
достаточность формальных данных, а не доказанную точность. Версия и SHA-256 формулы
сохраняются в `photo_scoring_version/hash`. Статус объекта и причина null сохраняются.

Пример: повреждения дороги 2/10 и тротуара 4/10 при полной различимости дают качества
8 и 6, итог `(0.14*8 + 0.12*6)/(0.14+0.12) = 7.08`. Отсутствие парковки не меняет его.
Если значимая часть других видимых объектов неоценима, покрытие падает и может запретить
выдачу итогового балла. Сравнивать снимки с разным набором объектов/покрытием следует
осторожно: два одинаковых балла могут описывать разное содержание.

Веса и пороги находятся в `photo_scoring.yaml`, путь — `photo_scoring_path` конфигурации.
После изменения формулы достаточно заново выполнить export; визуальная модель повторно
не вызывается. В ручных corrections исправляются исходные признаки и показатели,
а итог пересчитывается. В human_labels.csv можно независимо поставить photo_score
(допустима дробь с точкой), затем evaluate покажет его MAE отдельно от исходных показателей.

Для оценки качества формулы нужны пользовательские оценки тех же фото. Порог 60%,
коэффициент partial=0.5 и веса не объявляются научно установленными. Начальный набор
можно менять и калибровать; нельзя ранжировать дворы/районы простым средним этих фото.
