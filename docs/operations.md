# Эксплуатация

Команды выполняются из корня после установки окружения по README.
`start_analysis.ps1` использует `config.full.yaml`, `work` и `output`. Он продолжает
существующий реестр, но автоматически не импортирует новые папки.

## Ollama

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_ollama_safe.ps1
```

Сервер запускается скрыто, с `OLLAMA_NO_CLOUD=1`, одним запросом и одной загруженной
моделью. `LLAMA_ARG_CACHE_RAM=0` отключает дополнительный host prompt cache в backend,
который поддерживает эту настройку. Проверяйте применение по логам своей версии:
`work/ollama_safe.out.log` и `work/ollama_safe.err.log`.

Если порт 11434 занят, скрипт завершится с ошибкой. Он не останавливает чужой процесс.
`start_analysis.ps1` использует уже запущенный сервер без изменения его окружения.

## Повтор после текущего прохода

```powershell
$currentAnalysis = Get-Content .\work\analysis_status.json -Raw | ConvertFrom-Json
powershell -NoProfile -ExecutionPolicy Bypass -File .\retry_after_current.ps1 -ExpectedStartedAt $currentAnalysis.started_at
```

Повтор начнётся только после успешного завершения указанного прохода. Остановка,
ошибка или другой проход отменят ожидание. Дублирование планировщика блокируется.
Статус — `work/retry_schedule.json`. Отменить ожидание до запуска:

```powershell
New-Item -ItemType File -Path .\work\cancel_retry_schedule.request -Force
```

Перед новым планированием удалите оставшийся файл отмены.

## Лимиты и память

Обычный проход: 90 секунд на кадр; повтор только ошибок: 180 секунд.
В `config.full.yaml` один поток CPU готовит буфер из двух следующих кадров.
Низкая общая загрузка CPU сама по себе не означает остановку подготовки.

Runner периодически выгружает модель для освобождения host-памяти. Следующий запрос
загрузит те же веса. Защита `--memory-guard` по умолчанию отключена. При включении
следит за запасом виртуальной памяти Windows, прерывает запрос при малом запасе
и ограничивает восстановления без прогресса. Эта настройка не добавляет RAM.

Состояние — `work/analysis_status.json`, итоговый экспорт — `output/run_summary.json`.
Разделяйте время запроса модели и полное время кадра: подготовка, загрузка весов,
ориентация и повторы учитываются по-разному. Во время экспорта и выгрузки GPU может
простаивать.

Сохраняйте весь workspace. Для переноса SQLite остановите писателей и обработку;
учитывайте `state.sqlite-wal` и `state.sqlite-shm`, если они существуют. Не копируйте
активную базу как один произвольный файл. После смены путей проверьте источники фото;
не исправляйте `input_root` вручную.
